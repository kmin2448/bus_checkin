# 행사 체크인 · 숙소 안내 (bus_checkin)

행사 버스의 탑승 여부를 참가자가 직접 확인하고, 인솔자가 실시간으로 현황을 보며,
숙소 방 배정과 방키 수불까지 함께 다루는 앱입니다.
정적 페이지 4개 + Supabase RPC 로 이루어져 있습니다.

저장소 이름(`bus_checkin`)은 버스 기능만 있던 때 지은 것이라 지금 범위보다 좁습니다.

| 파일 | 용도 |
| --- | --- |
| `index.html` | 참가자 화면 — 첫 화면에서 **버스 탑승 확인 / 숙소 방 안내** 중 고른다 |
| `admin.html` | 인솔자 화면 — **탑승 · 숙박 현황** 한 화면. 위쪽 탭으로 가는 편 / 오는 편 / 숙박 |
| `manage.html` | 관리 화면 — 통합 시트 업로드·내려받기, 편별 작업, 안내 문구, 설정 |
| `rooms.html` | 예전 방키 주소 — `admin.html` 로 보낸다 |

`admin.html` 위쪽에는 **가는 편 · 오는 편 · 숙박** 세 칸이 있고, 칸마다 참가자에게
열어 둘지 정하는 On/Off 스위치가 붙어 있다. 이름을 누르면 그 현황이 바로 아래에
나온다 — 편은 탑승 명단, 숙박은 방 목록과 키 수불이다.

**명단 전체를 다루는 일은 `manage.html` 한 곳에서만** 한다(시트 업로드 · 덮어쓰기 ·
삭제 · 편 복사). 현장에서 자주 생기는 **한 명씩 넣고 빼는 일**은 `admin.html` 에서
바로 한다 — 탑승 명단은 편 탭의 "명단 추가", 방 배정은 숙박 탭 방 카드의 "인원".
둘 다 **이미 등록된 사람을 검색해 넣거나** 아예 새로 등록할 수 있고, 번호를 모르면
비워 둔 채로 넣을 수 있다.

되돌릴 수 없는 버튼(삭제 · 리셋 · 복사)은 브라우저 `confirm()` 을 쓰지 않는다.
대화상자가 반복되면 크롬이 "추가 대화상자 차단" 을 내놓고, 사용자가 그걸 체크하면
그 뒤로 `confirm()` 이 늘 `false` 를 돌려줘 **버튼이 먹통이 된 것처럼 보인다.**
그래서 버튼을 한 번 더 누르게 하고, 결과를 화면에 글로 적는다.
| `sql/` | Supabase(Postgres) 함수 · 설정 마이그레이션 |

빌드 과정은 없습니다. 네 파일을 그대로 정적 호스팅에 올리면 됩니다.

현재 주소는 <https://sdu-checkin.vercel.app> 입니다.
`master` 에 푸시하면 Vercel 이 자동으로 배포합니다. 다른 브랜치는 미리보기로만
올라가고 실제 주소는 바뀌지 않습니다.

## 데이터

Supabase 프로젝트 `sudcoss-pd-exhibition` (`jqvbuqgpgmqyviqdkzvl`).

- `bus_passengers` — 편(`leg`)별 명단과 `boarded_at`, 숙박일(`night1` · `night2`), `gender`.
  숙박일과 성별은 편과 무관하므로 전화번호 기준으로 그 사람의 모든 행에 같이 반영된다.
  성별은 시트에 적힌 대로 두고(`남` · `여` · `M` · `F` …) 화면에서 첫 글자로만 가른다.
  방 목록에는 방마다 성별 구성이 적히고, 남녀가 섞이면 빨갛게 **남녀 섞임** 으로 뜬다.
- `bus_room_slots` — 방 배정. `(전화번호, 방)` 한 쌍이 한 줄이라 **한 사람이 방을
  여러 개** 가질 수 있다. 방키 수령·반납 시각(`key_out_at` · `key_in_at`)도 여기 있다.
- `bus_requests` — 참가자가 보낸 명단 추가/번호 수정 요청
- `bus_groups` — 소속·팀명 선택지
- `bus_config` — 키/값 설정

`leg` 는 세 가지다.

| 값 | 뜻 |
| --- | --- |
| `out` | 가는 편 탑승 |
| `back` | 오는 편 탑승 |
| `stay` | 버스는 안 타고 숙박만 — 탑승 화면에는 안 나오고 숙소 안내만 받는다 |

`note`(소속)는 **소속 대학과 팀명을 합친 한 값**이다(예: `강원대학교 딸깍`).
합치는 일은 업로드 화면에서 하고, DB 에는 합쳐진 값만 들어간다.

### 연락처가 없는 사람

번호가 사람을 가르는 기준이라 빈 값으로 둘 수 없어서, `?소속/이름` 모양의
**자리표 번호**를 붙여 명단에 올린다. 숫자로 시작하지 않으므로 참가자가 번호를
넣어 조회하는 어떤 경로와도 겹치지 않는다.

- `admin.html` 의 종 아이콘 안에 **연락처 추가 필요** 로 뜬다. 번호를 넣으면
  양쪽 편 명단과 방 배정에 한꺼번에 반영되고, 그때부터 본인이 탑승 확인을 한다.
- 본인이 직접 명단 요청을 보내 승인해도 같은 결과가 된다 — 새로 생기지 않고
  자리표를 쓰던 그 사람의 번호가 채워진다.
- 번호를 채운 뒤 **시트를 다시 올려도 사람이 늘지 않는다**. 시트에 아직 번호가
  없어도 이름·소속이 같으면 이미 번호를 받은 그 사람으로 이어 붙인다.

### bus_config 키

| 키 | 뜻 |
| --- | --- |
| `admin_code` | 운영 코드 |
| `active_leg` | 운영자가 마지막으로 보던 편 (기본값 용도) |
| `collecting_out` / `collecting_back` | **편별 취합 On/Off** — 참가자 화면에 노출할 편 |
| `collecting` | 예전 단일 스위치. 두 편 중 하나라도 On 이면 `on` 으로 유지되는 호환용 값 |
| `event_title`, `bus_no`, `boarding_place` | 화면에 표시되는 행사 정보 |

### RPC

익명(anon) 키로 호출합니다.

- `bus_status()` — `out_open` / `back_open` / `legs`(켜져 있는 편 목록) / 행사 정보
- `bus_check_in(p_phone, p_leg default null)` — 탑승 확인
- `bus_check_out(p_phone, p_leg default null)` — 탑승 확인 취소
- `bus_request_add(p_name, p_phone, p_note default null, p_leg default null)`
- `bus_request_status(p_phone, p_leg default null)`
- `bus_group_options()`
- `bus_room_info(p_phone)` — 본인 방 정보만 반환(`rooms` 배열 · 방장 · 같은 방 명단 ·
  숙박일 · 안내 문구). 전체 배정표는 노출하지 않음
- `bus_admin(p_code, p_action, p_payload)` — 운영 코드로 보호되는 모든 운영 동작.
  `upload_sheet` 는 통합 시트 한 장으로 두 편 명단과 숙박을 한 번에 반영하고,
  `sheet` 는 지금 들어 있는 자료를 같은 형식으로 돌려준다.
  예전 방식인 `upload`(편 하나짜리)도 그대로 남아 있다
- `bus_room_admin(p_code, p_action, p_payload)` — 방 목록 / 키 수령·반납·취소 / 호수 입력 / 안내 문구 저장
- `bus_people_admin(p_code, p_action, p_payload)` — 한 명씩 넣고 빼기.
  `search`(이름·소속·번호로 찾기) / `add` · `del`(편) / `room_add` · `room_del` ·
  `room_leader`(방). bus_admin 이 이미 길어서 함수를 따로 뒀고, 보호 방식은 같다
- `bus_set_info(p_code, p_bus, p_place)`

`p_leg` 를 넘기지 않으면 켜져 있는 편 중 하나를 알아서 고르므로, 예전에 배포된
화면도 그대로 동작합니다.

## 참가자 첫 화면

`index.html` 을 열면 카드 두 개가 먼저 나온다.

- **버스 탑승 확인** — 켜져 있는 편이 카드에 적힌다. 두 편 다 꺼져 있으면
  "지금은 확인 전" 으로 바뀌고 눌러도 대기 화면으로 간다.
  이 기기에서 방금 확인을 마쳤으면 **(탑승 확인 완료)** 와 확인한 사람·시각이
  함께 적히고, 카드를 누르면 그 확인 카드로 되돌아가 취소도 할 수 있다.
  "다른 번호로 확인하기" 를 누르거나 탑승을 취소하면 표시가 사라진다.
  기기를 돌려 쓰므로 화면에만 두고 저장하지 않는다 — 새로 고치면 없어진다.
- **숙소 방 안내** — 번호로 본인 방만 조회한다. `rooms.html` 의 스위치로 열고 닫는다
  (`bus_config.collecting_room`). 꺼 두면 서버가 방 정보를 아예 내주지 않는다.

**켜져 있는 것만 카드로 보여 주고, 하나만 켜져 있으면 고르는 화면 없이 바로 그리로
들어간다.** 둘 다 꺼져 있으면 대기 화면이 뜬다.

켜져 있는 편의 명단에 없는 번호로 탑승 확인을 누르면
**"…탑승자 명단에 포함되어있지 않습니다. 탑승을 원하실 경우 운영진에게 명단 추가
요청을 하세요."** 가 뜨고, 바로 아래 버튼으로 명단 추가 요청을 보낼 수 있다.

## 저장해 둔 문자 메시지

단체 문자를 보낼 때 쓸 문구를 미리 저장해 둔다(`bus_sms_templates`).
쓰임새별로 목록이 나뉜다.

| `kind` | 쓰는 화면 |
| --- | --- |
| `bus` | `admin.html` — 탑승 관련 |
| `room` | `rooms.html` — 숙소 · 방키 관련 |

실제 발송은 서버가 하지 않는다. 운영자 휴대폰의 문자 앱을 `sms:` 링크로 열어
주고 마지막 전송은 사람이 직접 누른다.

## 편별 취합 On/Off

`admin.html` 의 탭은 **아래 명단을 어느 편으로 볼지**만 고릅니다.
참가자 화면에 무엇이 보일지는 그 아래 두 개의 On/Off 스위치가 정합니다.

- 두 편 모두 On → 참가자 화면 위쪽에 가는 편 / 오는 편 선택 버튼이 나타납니다.
- 한 편만 On → 그 편으로 바로 진행합니다.
- 두 편 모두 Off → 참가자 화면이 "지금은 확인 전입니다" 로 잠깁니다.

## 통합 시트

가는 편 탑승명단 · 오는 편 탑승명단 · 1일차 숙박 · 2일차 숙박을 **엑셀 한 장**에
담아 `manage.html` 에서 올린다.

### 열 제목 규칙

첫 줄이 열 제목이다. **제목에 아래 문구가 들어 있으면** 그 열로 읽는다. 열 순서는
상관없고, 표에 없는 제목은 건너뛴다. `이름` 과 `연락처` 열이 둘 다 있어야 첫 줄을
제목으로 인정한다.

| 열 제목 (해당 문구 포함) | 표시 형식 |
| --- | --- |
| `이름` · `성명` · `name` **(필수)** | 홍길동 |
| `연락처` · `휴대` · `전화` · `폰` · `번호` · `phone` **(필수)** | 010-1234-5678 — 비워 두면 연락처 추가 필요로 올라감 |
| `대학` · `학교` · `기관` | 강원대학교 |
| `팀명` · `팀` · `조명` | 딸깍 — 위 둘을 합쳐 `강원대학교 딸깍` 이 된다 |
| `소속` · `조` · `그룹` | 강원대학교 딸깍 — 대학·팀명 열이 없을 때만 |
| `성별` · `gender` | 남 · 여 |
| (`탑승`·`버스`·`승차`·`출발`·`복귀`) **+** `가는`·`출발` | **O** — 가는 편 탑승 |
| (`탑승`·`버스`·`승차`·`출발`·`복귀`) **+** `오는`·`복귀`·`귀가` | **O** — 오는 편 탑승 |
| (`숙박`·`투숙`·`숙소`) **+** `1`·`첫` | **O** — 1일차 숙박 |
| (`숙박`·`투숙`·`숙소`) **+** `2`·`둘째`·`이틀` | **O** — 2일차 숙박 |
| `배정` · `룸` · `room` · `방` | 트리플1 |
| `호수` · `호실` · `객실` | 1004호 |
| `방장` · `리더` · `인솔` · `leader` | **O** |
| `학과` · `전공` | 읽지 않고 건너뛴다 |

**O** 로 적힌 칸은 O 말고 아무 말이 적혀 있어도 표시로 본다(예: `버스`, `1박`).
비었거나 `-` · `X` · `없음` 이면 아니라고 본다.
그래서 `가는차 탑승` 도 `출발 8/10` 도 모두 가는 편 탑승으로 읽힌다.

- 표시 칸은 `O` 뿐 아니라 `버스` 처럼 아무 말이나 적혀 있어도 표시로 본다.
  비었거나 `-` · `X` · `없음` 이면 아니라고 본다.
- 두 탑승 칸이 모두 비어 있으면 버스를 안 타는 사람이므로 `leg='stay'` 로 들어가
  숙소 안내만 받는다.
- `소속 학과` · `학번` · `성별` · `비고` 열은 읽지 않고 넘어간다.
- **같은 사람이 여러 줄에 걸쳐 있으면 방을 여러 개 가진 사람으로 묶는다.** 번호가
  같은 두 줄은 한 사람이고, 방 배정만 둘 다 살아남는다.
- **연락처 칸이 비어 있어도 명단에 올라간다.** 운영자 화면에 "연락처 추가 필요" 로
  뜨고, 번호를 넣으면 그때부터 본인이 탑승 확인을 한다.
- 올리기 전에 무엇이 어디로 가는지 미리보기로 보여 주고, 방을 두 개 이상 쓰는
  사람과 연락처 없이 올라가는 사람을 짚어 준다.
- **이대로 반영**은 시트에 실린 사람만 손대고, **전체 덮어쓰기**는 명단을 통째로
  다시 채운다. 두 경우 모두 시트에 실린 사람의 편 구성은 시트대로 맞춰지므로,
  탑승 표시를 지우면 그 편 행도 사라진다.
- **빈 양식 내려받기** 로 형식을 받아 채워 넣을 수 있고, **지금 명단 내려받기** 로
  현재 자료를 같은 형식으로 받아 고쳐 다시 올릴 수 있다.

탑승·숙박 열이 하나도 없는 시트는 예전처럼 지금 고른 편의 명단으로만 올라간다.

## 마이그레이션

`sql/` 안의 파일은 Supabase 에 순서대로 적용된 델타입니다. 이미 존재하는
`bus_norm_phone` 같은 함수와 테이블은 전제로 두고 있습니다.

### 함수 권한 주의

Supabase 는 `public` 스키마에 새로 만들어지는 함수에 `anon` · `authenticated`
EXECUTE 를 **기본으로 붙입니다**. 그래서 함수를 만들면서 `revoke all ... from
public` 만 적어 두면 막힌 것처럼 보여도 실제로는 열려 있습니다.
방 목록처럼 통째로 새면 안 되는 헬퍼는 `revoke execute ... from anon,
authenticated` 로 **직접** 걷어내야 합니다(`20260807_lock_down_room_helpers.sql`).
